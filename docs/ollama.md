# Часто задаваемые вопросы: Ollama

## Как обновить Ollama?

Ollama на macOS и Windows автоматически загружает обновления. Нажмите на значок Ollama на панели задач или в строке меню, затем нажмите **«Restart to update»**, чтобы применить обновление. Обновления также можно установить, скачав последнюю версию [вручную](https://ollama.com/download/).

В Linux повторно запустите скрипт установки:

```shell
curl -fsSL https://ollama.com/install.sh | sh
```

## Как указать размер контекстного окна?

По умолчанию Ollama использует контекстное окно размером **4096 токенов**.

Это можно изменить с помощью переменной окружения `OLLAMA_CONTEXT_LENGTH`. Например, чтобы установить размер контекстного окна по умолчанию равным 8K:

```shell
OLLAMA_CONTEXT_LENGTH=8192 ollama serve
```

При использовании `ollama run` размер можно изменить с помощью `/set parameter`:

```shell
/set parameter num_ctx 4096
```

При использовании API укажите параметр `num_ctx`:

```shell
curl http://localhost:11434/api/generate -d '{
  "model": "llama3.2",
  "prompt": "Why is the sky blue?",
  "options": {
    "num_ctx": 4096
  }
}'
```

## Как узнать, была ли моя модель загружена на GPU?

Используйте команду `ollama ps`, чтобы увидеть, какие модели в данный момент загружены в память.

```shell
ollama ps
```

**Пример вывода:**

```text
NAME        ID            SIZE    PROCESSOR   UNTIL
llama3:70b  bcfb190ca3a7  42 GB   100% GPU    4 minutes from now
```

В столбце `PROCESSOR` отображается, в какую память была загружена модель:

- `100% GPU` — модель полностью загружена в GPU;
- `100% CPU` — модель полностью загружена в системную память;
- `48%/52% CPU/GPU` — модель частично загружена в системную память и частично в GPU.

## Как настроить сервер Ollama?

Сервер Ollama можно настроить с помощью переменных окружения.

### Настройка переменных окружения на Mac

Если Ollama запущен как приложение macOS, переменные окружения следует задавать с помощью `launchctl`:

1. Для каждой переменной окружения выполните `launchctl setenv`.

   ```bash
   launchctl setenv OLLAMA_HOST "0.0.0.0:11434"
   ```

2. Перезапустите приложение Ollama.

### Настройка переменных окружения в Linux

Если Ollama запущен как сервис systemd, переменные окружения следует задавать с помощью `systemctl`:

1. Отредактируйте systemd-сервис, выполнив `systemctl edit ollama.service`. Откроется редактор.

2. Для каждой переменной окружения добавьте строку `Environment` в секцию `[Service]`:

   ```ini
   [Service]
   Environment="OLLAMA_HOST=0.0.0.0:11434"
   ```

3. Сохраните файл и выйдите из редактора.

4. Перезагрузите конфигурацию `systemd` и перезапустите Ollama:

   ```shell
   systemctl daemon-reload
   systemctl restart ollama
   ```

### Настройка переменных окружения в Windows

В Windows Ollama наследует переменные окружения пользователя и системы.

1. Сначала завершите работу Ollama, нажав на его значок на панели задач.

2. Откройте **Settings** (Windows 11) или **Control Panel** (Windows 10) и найдите _environment variables_.

3. Нажмите **Edit environment variables for your account**.

4. Измените или создайте новую переменную для учетной записи пользователя, например `OLLAMA_HOST`, `OLLAMA_MODELS` и т. д.

5. Нажмите **OK/Apply**, чтобы сохранить изменения.

6. Запустите приложение Ollama из меню «Пуск» Windows.

## Как использовать Ollama через прокси?

Ollama загружает модели из интернета, поэтому для доступа к моделям может потребоваться прокси-сервер.

Используйте `HTTPS_PROXY`, чтобы перенаправить исходящие запросы через прокси. Убедитесь, что сертификат прокси установлен как системный сертификат.

Информацию о настройке переменных окружения на вашей платформе смотрите в разделе выше.

> **Примечание:** не устанавливайте `HTTP_PROXY`. Ollama не использует HTTP для загрузки моделей, только HTTPS. Установка `HTTP_PROXY` может нарушить клиентские подключения к серверу.

### Как использовать Ollama через прокси в Docker?

Docker-образ Ollama можно настроить для использования прокси, передав `-e HTTPS_PROXY=https://proxy.example.com` при запуске контейнера.

В качестве альтернативы можно настроить Docker daemon для работы через прокси. Инструкции доступны для Docker Desktop для [macOS](https://docs.docker.com/desktop/settings/mac/#proxies), [Windows](https://docs.docker.com/desktop/settings/windows/#proxies) и [Linux](https://docs.docker.com/desktop/settings/linux/#proxies), а также для [Docker daemon с systemd](https://docs.docker.com/config/daemon/systemd/#httphttps-proxy).

При использовании HTTPS убедитесь, что сертификат установлен как системный сертификат. При использовании самоподписанного сертификата может потребоваться создать новый Docker-образ.

```dockerfile
FROM ollama/ollama
COPY my-ca.pem /usr/local/share/ca-certificates/my-ca.crt
RUN update-ca-certificates
```

Соберите и запустите этот образ:

```shell
docker build -t ollama-with-ca .
docker run -d -e HTTPS_PROXY=https://my.proxy.example.com -p 11434:11434 ollama-with-ca
```

## Отправляет ли Ollama мои запросы и ответы на ollama.com?

Ollama работает локально. При локальном использовании Ollama разработчики не видят ваши запросы или данные.

При использовании облачных моделей ваши запросы и ответы обрабатываются для предоставления сервиса, однако это содержимое не хранится и не записывается в логи и никогда не используется для обучения моделей.

Собирается базовая информация об учетной записи и ограниченные метаданные использования, необходимые для предоставления сервиса. Они не включают содержимое запросов или ответов.

Ваши данные не продаются. Учетную запись можно удалить в любое время.

## Как отключить облачные функции Ollama?

Ollama может работать только в локальном режиме, если отключить облачные функции Ollama.

При отключении облачных функций вы потеряете возможность использовать облачные модели Ollama и веб-поиск.

Установите `disable_ollama_cloud` в `~/.ollama/server.json`:

```json
{
  "disable_ollama_cloud": true
}
```

Также можно установить переменную окружения:

```shell
OLLAMA_NO_CLOUD=1
```

После изменения конфигурации перезапустите Ollama.

После отключения в логах Ollama появится:

```text
Ollama cloud disabled: true
```

## Как использовать Ollama с прокси-сервером?

Ollama запускает HTTP-сервер и может быть доступен через прокси-сервер, например Nginx.

Для этого настройте прокси на перенаправление запросов и при необходимости установите требуемые заголовки.

Например, с Nginx:

```nginx
server {
    listen 80;
    server_name example.com;  # Replace with your domain or IP
    location / {
        proxy_pass http://localhost:11434;
        proxy_set_header Host localhost:11434;
    }
}
```

## Как использовать Ollama с ngrok?

Ollama можно использовать через различные приложения для туннелирования. Например, с Ngrok:

```shell
ngrok http 11434 --host-header="localhost:11434"
```

## Как использовать Ollama с Cloudflare Tunnel?

Для использования Ollama с Cloudflare Tunnel используйте флаги `--url` и `--http-host-header`:

```shell
cloudflared tunnel --url http://localhost:11434 --http-host-header="localhost:11434"
```

## Как разрешить дополнительным web origin обращаться к Ollama?

По умолчанию Ollama разрешает cross-origin-запросы с `127.0.0.1` и `0.0.0.0`.

Дополнительные origin можно настроить с помощью `OLLAMA_ORIGINS`.

Для расширений браузера необходимо явно разрешить шаблон origin расширения.

Чтобы разрешить доступ всем расширениям браузеров, установите `OLLAMA_ORIGINS` со значениями `chrome-extension://*`, `moz-extension://*` и `safari-web-extension://*`.

```shell
# Allow all Chrome, Firefox, and Safari extensions
OLLAMA_ORIGINS=chrome-extension://*,moz-extension://*,safari-web-extension://* ollama serve
```

При необходимости можно разрешить только конкретные расширения.

Информацию о настройке переменных окружения на вашей платформе смотрите в разделе [выше](#как-настроить-сервер-ollama).

## Где хранятся модели?

- macOS: `~/.ollama/models`
- Linux: `/usr/share/ollama/.ollama/models`
- Windows: `C:\Users\%username%\.ollama\models`

### Как изменить расположение моделей?

Если необходимо использовать другой каталог, установите переменную окружения `OLLAMA_MODELS`, указав нужный каталог.

> **Примечание:** в Linux при использовании стандартного установщика пользователь `ollama` должен иметь права на чтение и запись в указанном каталоге. Чтобы назначить каталог пользователю `ollama`, выполните:

```shell
sudo chown -R ollama:ollama <directory>
```

Информацию о настройке переменных окружения на вашей платформе смотрите в разделе [выше](#как-настроить-сервер-ollama).

## Почему сеть работает медленно в WSL2 на Windows 10?

и нажмите **Change adapter settings** в левой панели.

Отключите оба свойства.

## Как предварительно загрузить модель в Ollama, чтобы ускорить время ответа?

Если вы используете API, можно предварительно загрузить модель, отправив серверу Ollama пустой запрос.

Это работает как с endpoint `/api/generate`, так и с `/api/chat`.

Чтобы предварительно загрузить модель `mistral` через endpoint `generate`, используйте:

```shell
curl http://localhost:11434/api/generate -d '{"model": "mistral"}'
```

Для endpoint `chat`:

```shell
curl http://localhost:11434/api/chat -d '{"model": "mistral"}'
```

Чтобы предварительно загрузить модель через CLI, используйте:

```shell
ollama run llama3.2 ""
```

## Как оставить модель загруженной в памяти или сразу выгрузить ее?

По умолчанию модели остаются в памяти в течение **5 минут**, после чего выгружаются.

Это позволяет быстрее обрабатывать повторные запросы к LLM.

Если необходимо сразу выгрузить модель из памяти, используйте команду `ollama stop`:

```shell
ollama stop llama3.2
```

При использовании API параметр `keep_alive` для endpoint `/api/generate` и `/api/chat` позволяет указать, как долго модель должна оставаться в памяти.

Параметр `keep_alive` может принимать:

- строку с длительностью, например `"10m"` или `"24h"`;
- количество секунд, например `3600`;
- любое отрицательное число, которое оставит модель загруженной в памяти, например `-1` или `"-1m"`;
- `0`, что выгрузит модель сразу после генерации ответа.

Например, чтобы предварительно загрузить модель и оставить ее в памяти:

```shell
curl http://localhost:11434/api/generate -d '{"model": "llama3.2", "keep_alive": -1}'
```

Чтобы выгрузить модель и освободить память:

```shell
curl http://localhost:11434/api/generate -d '{"model": "llama3.2", "keep_alive": 0}'
```

Также можно изменить время, в течение которого **все модели** остаются загруженными в память, задав переменную окружения `OLLAMA_KEEP_ALIVE` при запуске сервера Ollama.

Переменная `OLLAMA_KEEP_ALIVE` использует те же типы значений, что и параметр `keep_alive`.

Информацию о правильной настройке переменной окружения смотрите в разделе, посвященном [настройке сервера Ollama](#как-настроить-сервер-ollama).

Параметр API `keep_alive` для endpoint `/api/generate` и `/api/chat` имеет приоритет над настройкой `OLLAMA_KEEP_ALIVE`.

## Как управлять максимальным количеством запросов, которые сервер Ollama может поставить в очередь?

Если сервер получает слишком много запросов, он вернет ошибку `503`, означающую, что сервер перегружен.

Количество запросов, которые могут находиться в очереди, можно изменить с помощью `OLLAMA_MAX_QUEUE`.

## Как Ollama обрабатывает параллельные запросы?

Ollama поддерживает два уровня параллельной обработки.

Если в системе достаточно свободной памяти — системной памяти при использовании CPU inference или VRAM при GPU inference — одновременно может быть загружено несколько моделей.

Для конкретной модели, если при ее загрузке достаточно свободной памяти, Ollama настраивает ее для параллельной обработки запросов.

Если свободной памяти недостаточно для загрузки новой модели, пока одна или несколько моделей уже загружены, все новые запросы будут помещены в очередь до тех пор, пока новая модель не сможет быть загружена.

По мере того как ранее загруженные модели становятся неактивными, одна или несколько из них будут выгружены, чтобы освободить место для новой модели.

Запросы из очереди обрабатываются по порядку.

При использовании GPU новые модели должны полностью помещаться в VRAM, чтобы одновременно можно было загружать несколько моделей.

Параллельная обработка запросов одной моделью приводит к увеличению размера контекста пропорционально количеству параллельных запросов.

Например, контекст размером 2K при 4 параллельных запросах фактически потребует контекст размером **8K** и дополнительного выделения памяти.

Следующие настройки сервера можно использовать для управления параллельной обработкой в большинстве систем:

- `OLLAMA_MAX_LOADED_MODELS` — максимальное количество моделей, которые могут быть одновременно загружены, если они помещаются в доступную память. По умолчанию — 3 × количество GPU или 3 для CPU inference.
- `OLLAMA_NUM_PARALLEL` — максимальное количество параллельных запросов, которые каждая модель может обрабатывать одновременно. По умолчанию — 1. Требуемая RAM масштабируется как `OLLAMA_NUM_PARALLEL * OLLAMA_CONTEXT_LENGTH`.
- `OLLAMA_MAX_QUEUE` — максимальное количество запросов, которые Ollama может поставить в очередь при занятости сервера до того, как начнет отклонять дополнительные запросы. По умолчанию — 512.

**Примечание:** в Windows с Radeon GPU по умолчанию разрешена загрузка только одной модели из-за ограничений ROCm v5.7 на получение информации о доступной VRAM.

После появления ROCm v6.2 Windows Radeon будет использовать указанные выше значения по умолчанию.

Можно включить параллельную загрузку моделей на Radeon в Windows, однако необходимо убедиться, что одновременно не загружается больше моделей, чем помещается в VRAM GPU.

## Как Ollama загружает модели на несколько GPU?

При загрузке новой модели Ollama оценивает необходимый объем VRAM и сравнивает его с доступным объемом.

Если модель полностью помещается на любом одном GPU, Ollama загрузит ее на этот GPU.

Обычно это обеспечивает лучшую производительность, поскольку уменьшает объем данных, передаваемых через PCI-шину во время inference.

Если модель целиком не помещается ни на одном GPU, она распределяется между всеми доступными GPU.

## Как включить Flash Attention?

Flash Attention — функция, поддерживаемая большинством современных моделей, которая может значительно снизить потребление памяти по мере увеличения размера контекста.

Ollama автоматически использует Flash Attention, если выбранный backend и устройства его поддерживают.

Чтобы принудительно включить Flash Attention, установите `OLLAMA_FLASH_ATTENTION=1` при запуске сервера Ollama.

Чтобы отключить его:

```shell
OLLAMA_FLASH_ATTENTION=0
```

## Как установить тип квантования для K/V cache?

Контекстный K/V cache можно квантовать, чтобы значительно уменьшить потребление памяти при включенном Flash Attention.

Для использования квантованного K/V cache в Ollama можно установить следующую переменную окружения:

- `OLLAMA_KV_CACHE_TYPE` — тип квантования K/V cache. По умолчанию — `f16`.

> **Примечание:** в настоящее время это глобальная настройка — то есть все модели будут использовать указанный тип квантования.

Доступные в настоящее время типы квантования K/V cache:

- `f16` — высокая точность и высокое потребление памяти (по умолчанию);
- `q8_0` — 8-битное квантование, использует примерно в 2 раза меньше памяти, чем `f16`, при очень небольшой потере точности. Обычно это практически не влияет на качество модели и рекомендуется, если вы не используете `f16`;
- `q4_0` — 4-битное квантование, использует примерно в 4 раза меньше памяти, чем `f16`, с небольшой или средней потерей точности, которая может быть более заметной при больших размерах контекста.

Влияние квантования cache на качество ответов зависит от модели и задачи.

Модели с большим количеством GQA, например Qwen2, могут сильнее терять точность из-за квантования, чем модели с небольшим количеством GQA.

Возможно, придется поэкспериментировать с разными типами квантования, чтобы найти оптимальный баланс между потреблением памяти и качеством.

## Где найти мой публичный ключ Ollama?

Ваш **Ollama Public Key** — это публичная часть пары ключей, которая позволяет локальному экземпляру Ollama взаимодействовать с [ollama.com](https://ollama.com).

Он необходим для:

- отправки моделей в Ollama;
- загрузки приватных моделей из Ollama на вашу машину;
- запуска моделей, размещенных в [Ollama Cloud](https://ollama.com/cloud).

### Как добавить ключ

- **Войти через страницу Settings** в приложении **Mac** или **Windows**.
- **Войти через CLI:**

```shell
ollama signin
```

- **Вручную скопировать и вставить ключ** на странице [Ollama Keys](https://ollama.com/settings/keys).

### Где находится публичный ключ Ollama

| ОС | Путь к `id_ed25519.pub` |
| :- | :- |
| macOS | `~/.ollama/id_ed25519.pub` |
| Linux | `/usr/share/ollama/.ollama/id_ed25519.pub` |
| Windows | `C:\Users\<username>\.ollama\id_ed25519.pub` |

> **Примечание:** замените `<username>` на фактическое имя пользователя Windows.

## Как запретить Ollama запускаться при входе в систему?

Ollama для Windows и macOS регистрируется как приложение, запускаемое при входе в систему, во время установки.

Это можно отключить, если вы не хотите, чтобы Ollama запускался автоматически.

Ollama будет сохранять эту настройку после обновлений, пока приложение не будет удалено.

**Windows**

- Откройте `Task Manager`.
- Перейдите на вкладку `Startup apps`.
- Найдите `ollama`.
- Нажмите **Disable**.

**macOS**

- Откройте **Settings**.
- Найдите **Login Items**.
- Найдите запись `Ollama` в разделе **Allow in the Background**.
- Отключите переключатель.
